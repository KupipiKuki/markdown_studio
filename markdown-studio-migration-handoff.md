## Known editor defect to carry into planning

The user observed that the line-number gutter stays fixed when the editor scrolls. Source review confirmed that the editor scroll handler updates the preview without moving the gutter. The gutter also uses a different computed line height, and soft wraps add visual rows only in the editor. Both conditions can cause alignment drift. The audited artifact contains this behavior. [Editor styles](https://github.com/KupipiKuki/markdown_studio/blob/c0da234d3640976e75c6cefe4c3353c9632f8e86/markdown_studio_phase_0/final/markdown_studio.html#L597-L625) · [Scroll handler](https://github.com/KupipiKuki/markdown_studio/blob/c0da234d3640976e75c6cefe4c3353c9632f8e86/markdown_studio_phase_0/final/markdown_studio.html#L3624-L3645)

Proposed migration acceptance check. Each logical line number stays aligned with the first visual row of that line throughout a long document, including when lines wrap or the pane is resized. Verify with preview scroll sync on and off, and after switching tabs. Reproduce on the current live baseline before assigning the fix to a migration batch.

2. **Inventory live compatibility.** At the pinned reference, both artifacts use `markflow_editor_state_v2` for tabs and active tab, `markflow_view_mode_v2` for pane state, and `markflow_viewer_full_width`. The live script also uses `markflow_theme` and a cross-Studio transfer flow through `gemini_studio_bus` and `gemini_studio_transfer_queue_v1`. Verify schemas, message contracts, and launch origins on the current live branch. Cover existing saved state, reload, and cross-Studio transfer with synthetic fixtures in an isolated profile. [Live script](https://github.com/KupipiKuki/markdown_studio/blob/c0da234d3640976e75c6cefe4c3353c9632f8e86/scripts/markdown-studio.html)
3. **Define migration acceptance and rollback.** Specify the target branch, change batches, and tests through the normal live entry point. Include Mermaid rendering and Studio actions, editor controls and gutter, document persistence, transfers, clipboard, HTML/SVG/PNG export, and tall-diagram print. Record what is tested on each supported launch origin. Pin the pre-migration live version and prove that restoring it preserves saved documents and preferences.
4. **Preserve the review sequence.** After the plan is agreed, the coder implements on a migration branch. QA/QC tests one frozen candidate and retains browser-specific results and sample outputs. The independent auditor makes the migration gate decision against those criteria.
