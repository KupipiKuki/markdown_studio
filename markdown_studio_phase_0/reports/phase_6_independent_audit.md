### A6-01 reproduction

The audit evaluated the exact `ensurePreviewRenderReady` function from the pinned HTML with a controlled scheduler. The active tab began at `initial`. Each simulated render completion changed the active tab content, and each preview refresh queued a debounce. The call resolved after the tenth edit with `{ rendered: "edit 9", latest: "edit 10", pendingDebounce: true }`. This was a deterministic function-level reproduction. The existing P5-02 covers an edit followed by a stable render, which passed in the independent rerun.

## Conditions for a new gate decision

1. Ensure export, rendered HTML copy, and print abort with clear retry feedback if the latest generation cannot be completed. Regress sustained edits through the retry limit and verify the normal successful path.
2. On one new frozen candidate, run the user-facing G5 actions. Capture and reopen HTML, SVG, and PNG exports, verify current Mermaid and MathJax content, confirm actual dimensions and label fidelity, and inspect tall-diagram PDF output. Record unsupported operations as blocked and document any accepted deferral with impact and acceptance.
3. Complete the pending control and template assertions, record what was exercised on local-file and HTTP origins, and preserve browser-specific artifacts. Update the package entry point, final gate counts, and checksums to match the evidence.
